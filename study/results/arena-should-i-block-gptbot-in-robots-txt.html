What the engine reads

  1. wpghost.com Frequently asked questions › Is robots.txt enough to block GPTBot?

    For GPTBot itself, yes, because OpenAI states GPTBot honours it. It doesn’t stop scrapers that forge a user agent or skip robots.txt. A rewrite-layer rule returning 403 covers those.

  2. wpghost.com How to block GPTBot on WordPress in two layers

    Blocking a crawler well takes two layers. robots.txt is a published request that compliant crawlers read and honour. A server rule is the enforcement that applies when a request lies about who it is. Call the pair Dual-Layer Crawler Control. It matters because roughly 43% of the web runs on WordPress (W3Techs), which makes it a standing target for scrapers that forge a browser user agent and ignore robots.txt.

  3. anglera.com Frequently asked questions › Does blocking GPTBot remove my site from ChatGPT?

    No. GPTBot is OpenAI's training crawler. ChatGPT's search features are served by OAI-SearchBot, a separate agent with its own robots.txt token. Blocking GPTBot leaves ChatGPT search access unaffected, and blocking OAI-SearchBot is what removes you from those results.

  4. anglera.com GPTBot › Configuring it

    GPTBot obeys robots.txt and OpenAI publishes IP ranges for verification. Verify by IP as well as user-agent string, since the string is trivially spoofed by scrapers. And if you block, expect a lag: robots.txt changes affect future crawls, not what was already collected.

    robots.txt is advisory. A scraper that spoofs GPTBot’s user-agent string, or never read your robots.txt, walks straight past it. So the block also belongs at the request layer, where a rule matches the user agent and rejects the request before WordPress loads.
